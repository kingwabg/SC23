# SC23 Table Single-Boundary Test Checklist

## 목적

이 문서는 SC23 `Rooster` 표 편집기에서 `한 칸 경계` 이동 동작만 집중적으로 검증하기 위한 수동 테스트 기준서입니다.

특히 아래 동작을 확인하는 것이 목적입니다.

- 한 칸의 경계를 아래나 위로 이동해도 옆칸 경계는 가만히 있어야 한다.
- 옆칸 경계는 내가 따로 잡았을 때 독립적으로 아래, 위 방향 모두 이동 가능해야 한다.
- 한 번 이동한 뒤에도 같은 경계를 다시 잡아 반대 방향으로 복귀할 수 있어야 한다.
- 다른 행/열까지 넘어가면서 표 구조가 깨지면 안 된다.

---

## 용어 정의

- `현재칸`: 지금 마우스로 경계를 잡아 이동하는 셀
- `옆칸`: 현재칸과 같은 행 또는 같은 열에 붙어 있지만, 지금 직접 잡지 않은 셀
- `한 칸 경계`: `Shift`를 누른 상태에서 표시되는 셀 구간 전용 경계선
- `정상`: 잡은 칸만 이동하고, 다른 칸은 그대로 유지되며, 다시 반대 방향으로도 이동 가능한 상태

---

## 테스트 환경

- 페이지: `http://localhost:5173/meetings`
- 계정: `admin / admin777`
- 권장 표: `3 x 3`
- 권장 확대: 브라우저 확대 `100%`
- 테스트 모드: `Shift + 셀 경계 드래그`

---

## 사전 준비

1. 회의록 페이지를 연다.
2. 빈 문서에 `3 x 3` 표를 삽입한다.
3. 표 크기와 셀 높이는 기본 상태로 둔다.
4. 테스트 중간에 구조가 깨지면 새 표를 다시 만들어 이어간다.

---

## 핵심 합격 기준

- `Shift`를 누르고 현재칸의 아래 경계를 아래로 내리면, 바로 아래칸만 영향을 받고 옆칸 경계는 움직이지 않아야 한다.
- 그 다음 옆칸 경계를 따로 잡으면, 처음 칸의 이동 방향과 무관하게 위/아래 둘 다 이동 가능해야 한다.
- 같은 경계를 위쪽 셀에서 잡든 아래쪽 셀에서 잡든 같은 선으로 인식되어야 한다.
- 열도 동일하게 동작해야 한다.
- 경계를 다른 행/열 구간까지 넘기려 할 때는 더 이상 이동되지 않아야 한다.
- 이동 후 표가 찌그러지거나 예상치 못한 추가 선이 생기면 실패다.

---

## 기본 행 테스트

### TC-R1 현재칸 아래 이동

- 준비: 첫 번째 행 가운데 셀의 아래 경계를 잡는다.
- 동작: `Shift`를 누른 채 경계를 아래로 드래그한다.
- 기대 결과:
  - 현재칸 높이만 커진다.
  - 바로 아래칸 높이만 줄어든다.
  - 오른쪽 또는 왼쪽 옆칸 경계는 그대로다.

### TC-R2 옆칸은 가만히 유지

- 준비: `TC-R1` 직후 상태
- 동작: 아무 것도 잡지 않고 눈으로 옆칸 경계를 확인한다.
- 기대 결과:
  - 현재칸 옆칸의 경계 위치는 자동으로 따라 움직이지 않는다.
  - 옆칸도 같이 같은 방향으로 잠기지 않는다.

### TC-R3 옆칸 독립 아래 이동

- 준비: `TC-R1` 직후 상태
- 동작: 바로 옆칸의 같은 행 경계를 다시 잡고 아래로 이동한다.
- 기대 결과:
  - 옆칸도 별개로 아래로 이동 가능하다.
  - 처음 조절한 칸의 경계는 그대로 유지된다.

### TC-R4 옆칸 독립 위 이동

- 준비: `TC-R3` 또는 `TC-R1` 직후 상태
- 동작: 옆칸 경계를 위로 올린다.
- 기대 결과:
  - 옆칸이 아래 방향으로만 잠기지 않는다.
  - 위 방향으로도 이동된다.
  - 현재칸 경계는 그대로다.

### TC-R5 같은 경계 복귀

- 준비: 한 칸 경계를 한 번 아래로 내린 상태
- 동작:
  1. 같은 경계를 아래쪽 셀의 윗선에서 다시 잡는다.
  2. 원래 위치 쪽으로 위로 올린다.
- 기대 결과:
  - 같은 경계가 다시 잡힌다.
  - 원래 중간 위치 쪽으로 복귀 가능하다.

### TC-R6 다른 행 넘김 금지

- 준비: 중간 행 경계 선택
- 동작: 아래로 계속 끌어서 다음 행 구간까지 넘기려 시도한다.
- 기대 결과:
  - 바로 아래칸 범위를 넘기면 더 이상 이동되지 않는다.
  - 표가 깨지지 않는다.
  - 새로운 유령 선이 생기지 않는다.

---

## 기본 열 테스트

### TC-C1 현재칸 오른쪽 이동

- 준비: 가운데 셀의 오른쪽 경계를 잡는다.
- 동작: `Shift`를 누른 채 오른쪽으로 드래그한다.
- 기대 결과:
  - 현재칸 너비만 넓어진다.
  - 바로 오른쪽칸 너비만 줄어든다.
  - 위/아래 같은 열의 다른 칸 경계는 그대로다.

### TC-C2 옆칸 독립 왼쪽 이동

- 준비: `TC-C1` 직후 상태
- 동작: 옆칸 경계를 따로 잡고 왼쪽으로 이동한다.
- 기대 결과:
  - 옆칸도 별개로 왼쪽 이동 가능하다.
  - 처음 칸의 경계를 강제로 따라가지 않는다.

### TC-C3 옆칸 독립 오른쪽 이동

- 준비: `TC-C2` 또는 `TC-C1` 직후 상태
- 동작: 옆칸 경계를 오른쪽으로 이동한다.
- 기대 결과:
  - 옆칸이 한 방향으로만 잠기지 않는다.
  - 처음 칸과 독립적으로 움직인다.

### TC-C4 같은 경계 복귀

- 준비: 한 열 경계를 한 번 오른쪽으로 이동한 상태
- 동작:
  1. 같은 경계를 오른쪽 셀의 왼선에서 다시 잡는다.
  2. 다시 왼쪽으로 복귀한다.
- 기대 결과:
  - 같은 경계를 반대쪽 셀에서도 다시 잡을 수 있다.
  - 원래 위치로 복귀할 수 있다.

### TC-C5 다른 열 넘김 금지

- 준비: 중간 열 경계 선택
- 동작: 계속 끌어서 다음 열 구간까지 넘기려 시도한다.
- 기대 결과:
  - 바로 옆칸 범위를 넘기면 더 이상 이동되지 않는다.
  - 표 구조가 깨지지 않는다.

## 왕복 테스트

### TC-B1 현재칸 왕복

- 동작:
  1. 현재칸 경계를 아래로 이동
  2. 같은 경계를 다시 위로 이동
- 기대 결과:
  - 현재칸은 아래/위 모두 왕복 가능하다.
  - 한쪽 방향만 되는 잠김 현상이 없어야 한다.

### TC-B2 옆칸 왕복

- 동작:
  1. 현재칸 경계를 아래로 이동
  2. 옆칸 경계를 위로 이동
  3. 옆칸 경계를 다시 아래로 이동
- 기대 결과:
  - 옆칸도 별개로 왕복 가능하다.
  - 현재칸이 먼저 움직였다는 이유로 같은 방향만 따라가면 실패다.

## 구조 안정성 테스트

### TC-S1 표 선 추가 생성 여부

- 동작: 행/열 경계를 여러 번 왕복 이동한다.
- 기대 결과:
  - 의도하지 않은 새로운 선이 생기지 않는다.
  - 사라지지 않는 유령 행/열이 남지 않는다.

### TC-S2 표 깨짐 여부

- 동작: 현재칸, 옆칸, 다시 현재칸 순서로 번갈아 이동한다.
- 기대 결과:
  - 특정 열이 비정상적으로 길어지거나 잘리지 않는다.
  - 셀 병합처럼 보이는 깨짐이 생기지 않는다.

### TC-S3 재선택 가능 여부

- 동작: 한 번 이동 후 마우스를 떼고, 같은 선이나 옆 선을 다시 잡는다.
- 기대 결과:
  - 다시 잡는 동작이 자연스럽다.
  - 특정 선만 다시 못 잡히는 현상이 없어야 한다.

---

## 실패로 기록할 증상

- 현재칸을 내렸더니 옆칸도 같은 방향으로만 움직임
- 현재칸은 왕복되는데 옆칸은 한 방향으로만 잠김
- 아래쪽 셀에서 같은 선을 다시 못 잡음
- 위쪽 셀과 아래쪽 셀에서 같은 선으로 인식되지 않음
- 다른 행/열을 넘기면서 표가 깨짐
- 유령 행선, 유령 열선이 남음
- 마우스를 떼면 셀이 자동 선택됨
- 경계 hover는 보이는데 실제 드래그 결과가 다른 선에 적용됨

## 우선 확인할 핵심 시나리오

가장 먼저 이 4개만 보면 현재 이슈를 빠르게 판별할 수 있습니다.

1. 현재칸 경계를 아래로 이동한다.
2. 옆칸 경계는 가만히 있는지 본다.
3. 옆칸 경계를 위로 이동해본다.
4. 다시 옆칸 경계를 아래로 이동해본다.

이 4단계가 모두 자연스럽게 되면, 현재 가장 큰 `한칸 경계 독립 이동` 이슈는 상당 부분 해결된 것으로 봐도 됩니다.
